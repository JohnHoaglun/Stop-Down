# Architecture

`SwiftUI views → exposure domain → camera/persistence/Photos adapters`

The pure, deterministic exposure-math domain lives in `Stop-Down/Domain/`:

- `ExposureAxis` / `StopIncrement` — the three dial axes (ISO, aperture, shutter) and full/half/third increments.
- `ExposureMath` — EV100 and per-axis stop/value conversions (pure math).
- `ExposureValueTables` — the canonical conventional dial values and their display labels.
- `StopQuantizer` — rounds an arbitrary stop offset onto a full/half/third grid (ties round down).
- `ExposureSolver` — solves any two dial values for the third at a target EV, with filter compensation.
- `EquivalentCombinationFinder` — enumerates the nearby equivalent combinations shown below the wheels (spec §4.3): the locked axis keeps its value, the anchor axis steps through every table offset within ±1 full stop, and the third axis is solved for the same target EV. Out-of-range solves and the current combination are dropped; rows come back nearest-first, capped.

The pure, deterministic meter core also lives in `Stop-Down/Domain/`:

- `MeterSample` — one timestamped sample carrying optional native metadata (ISO/duration/aperture) and optional luminance diagnostics (center/spot luma, clipping, noise); derives `metadataEV100` from the metadata.
- `MeterReading` — a displayable reading: final EV, metadata EV, source diagnostics, mode, lens, `ConfidenceLevel`, confidence reason, and filter compensation.
- `ConfidenceLevel` — `.stable`, `.stabilizing`, `.dark`, `.clipped`, `.stale`, `.unavailable`, with `isLowConfidence` and user-facing `guidance`.
- `MeterConfiguration` — stability (count/window/tolerance), 10 Hz rate cap, and confidence thresholds (min luma, max clipping, max noise, and the luma ceiling under which high noise also counts as dark, `noiseJudgeLumaCeiling`).
- `MeteringMode` / `NormalizedPoint` — center-weighted vs. spot metering and the normalized Spot point (stored in the capture buffer's unit square).
- `SpotPointConverter` — pure, `nonisolated` screen↔capture coordinate math for the Spot point: a screen tap is mapped through the 90° CW back-camera rotation and the aspect-fill preview crop into the buffer's unit square (and back, for drawing the reticle), so the point of interest, the luma Spot box, and the reticle all agree (spec FR-3, orientation).
- `MeterEngine` — deterministic stateful engine over sample timestamps (no hidden clock): 10 Hz rate cap, rolling 300 ms smoothing window, stability (≥3 samples within ±0.1 EV), and confidence precedence (clipped → dark → stable → stabilizing; dark = luma below `minJudgeLuma`, or noise above `maxNoise` while luma is below `noiseJudgeLumaCeiling`). Missing metadata preserves the last reading as `.stale`, or reports `.unavailable` when none exists. `reset()` clears the window, rate cap, and current reading so a feed swap never answers with the old feed's state.

The metering layer lives in `Stop-Down/Metering/`, between the feed and the UI:

- `MeteringSource` — the feed seam that emits `MeterSample`s and applies metering configuration (mode/Spot context, `applyConfiguration` is a protocol requirement so calls reach the concrete source through the existential). `CameraMeteringSource` and `TestMeterSource` both conform. Two optional refinements narrow feeds that support more: `PreviewProviding` (`previewSession` + nominal `previewBufferSize`) and `LensProviding` (`availableLensNames`); the controller reads both through the existential and falls back gracefully for fixture feeds.
- `CameraMeteringSource` — the real AVFoundation feed. `start()` requests camera access once, configures a 1920×1080 video session with the selected lens, and reads native AE metadata (ISO, duration, aperture) per frame as the EV authority. It exposes the session for the preview layer and the discovered lens list (spec FR-1), swaps the video input when the lens changes, locks device configuration only around point-of-interest and exposure-mode commits, re-reads the device per session queue, and re-syncs permission state on `UIApplication.didBecomeActiveNotification` (the iOS 27 SDK removed `AVCaptureDeviceWasAuthorized`). On denial or session failure it reports `.unavailable` with a reason instead of fabricating a reading.
- `TestMeterSource` — DEBUG-only fixture feed at ~10 Hz with stable/unstable/dark/clipped scenarios and pause/step (spec 8.5); it is always presented as test data, never a true reading.
- `ExposureState` — pure dial state: exactly two pinned axes (the locked axis and the anchor axis) plus one solved axis recomputed by `ExposureSolver` for the target EV (spec §4.3).
- `MeteringController` — `@MainActor @Observable` controller that owns the `MeterEngine` and a `MeteringSource`, keeps a live reading plus a frozen held reading, and exposes configuration and dial operations. While held, incoming samples update the live reading but never re-solve the dials; turning a dial while Live auto-enters Hold first so the edit is applied against a stable target (spec §4.3). It also exposes `nearbyCombinations` (the current dial state and displayed EV run through `EquivalentCombinationFinder`) and `applyCombination` (sets the anchor dial to the row's value and re-solves the third axis). It surfaces feed capabilities through the seam: `previewSession` (for the preview layer), `previewBufferSize` (for Spot-space math), and `availableLensNames` (for the lens picker), with graceful fallbacks for fixture feeds. The default feed is the camera; DEBUG builds can swap the feed at runtime (`replaceSource` resets engine state first).

The camera layer lives in `Stop-Down/Camera/`, isolated behind the seam:

- `CameraLens` / `CameraLensCatalog` — the lenses the current device supplies on the back position (Ultra Wide, Wide, Tele), discovered via `AVCaptureDevice.DiscoverySession`; the catalog prefers the wide lens (spec FR-1) and exposes only what the device provides.
- `CameraFrameCoordinator` — owns the `AVCaptureSession` (1920×1080 preset, also exposed for the preview layer) and serializes per-frame work off the capture session queue, hopping samples to `MainActor` for delivery. `start(deviceType:)` resolves the lens device (falling back to the default back camera); `setLens` swaps the video input on the running session inside a begin/commit configuration and restores the previous input if the swap fails, then re-applies the stored point of interest to whichever device won.
- `LuminanceAnalyzer` — pure, `nonisolated` analysis of biplanar (Y-U-V) pixel buffers: a stride-8 Y grid for center-weighted luminance and a 16×16 Spot box around the capture-space normalized point, reporting luma, clipping, and noise diagnostics. Non-biplanar frames are rejected (`hasLuma == false`) rather than misread.

`Stop-Down/Views/MeterScreen.swift` renders the spec's hybrid meter over the live preview (spec §4.2, §4.7): the framed scene as a full-bleed background (`CameraPreviewView`, the app's only `UIViewRepresentable`; a plain dark backdrop when the feed has no session), a responsive circular EV dial (192 pt, shrinking to 160 pt on short screens) with an explicit "EV" unit label and the thin 6 pt state ring, the lens and mode bar pinned to the top safe area, the lockable equivalent-exposure wheels, the compact nearby-combinations list (the three nearest rows; each row applies on tap), filter compensation, stop-increment picker, and the Hold/Live + Save bar pinned to the bottom safe area (which also hosts the compact About button), with a Spot reticle positioned by the inverse `SpotPointConverter` mapping and tap-to-meter in Spot mode (screen→capture before the point is stored). The About button presents a release-readiness sheet showing the app name, the version read from `Bundle.main` (marketing version plus build number, never hardcoded), the local-first privacy statement, and the support link. The confidence banner occupies a fixed 48 pt slot so its appearance never reflows the dial. The screen forces the dark scheme and uses the spec §4.7 design tokens. The UI talks only to `MeteringController`, so swapping the feed never touches the layout.

Exposure math and the meter engine are pure and deterministic and independent of camera hardware and UI. AVFoundation supplies native auto-exposure metadata as the EV authority through `CameraMeteringSource`. Luminance analysis only expresses confidence/instability and never alters the reported EV. Photos saves, SwiftData history, and haptics will be isolated behind testable adapters.
