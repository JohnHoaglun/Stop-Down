# Decisions

| Date | Decision | Rationale |
| --- | --- | --- |
| 2026-09-15 | Native auto-exposure metadata is the EV authority. | The product is a reflected-light exposure guide, not a laboratory calibration tool. |
| 2026-09-15 | Keep the app local-first. | The product requires no accounts, analytics, network calls, or app-operated cloud sync. |
| 2026-09-22 | Canonical dial values are conventional photographic numbers, not exact stop grids. | The spec's third-stop lists are nice-number fixtures and the standard full/half series do not sit on exact factor-of-two grids. The dial value is the source of truth; stop offsets are always derived from it, never the reverse. |
| 2026-09-22 | ND-filter compensation lowers the target setting-EV (`target − comp`). | A filter removes light, so the dial setting must be slower (more exposure) to compensate. |
| 2026-09-22 | The meter engine is pure and timestamp-driven; luminance never changes EV. | The EV comes only from native metadata. Luminance/clipping/noise only set `ConfidenceLevel` (stabilizing/dark/clipped), so confidence can never silently alter a reported exposure. |
| 2026-09-22 | Stability = ≥3 recent samples within ±0.1 EV over a rolling 300 ms window, sampled at ≤10 Hz. | A short, bounded window gives a fast "live" feel while rejecting flicker and hand shake; the 10 Hz cap keeps CPU and smoothing predictable. |
| 2026-09-22 | Missing metadata preserves the last reading as `.stale`; if none exists it reports `.unavailable`. | The camera occasionally emits frames without complete AE metadata; showing a clearly-labeled stale value is more useful than a hard blank, while `.unavailable` keeps the UI honest before the first reading. |
| 2026-09-22 | The meter UI is built against the `MeteringSource` seam, driven by the DEBUG `TestMeterSource` before the real camera exists. | Spec 8.5 calls for a Test Meter so the experience can be built, demoed, and tested without ambient light or camera permission; the real AVFoundation source can be swapped in without touching the UI. |
| 2026-09-22 | Exactly two dial axes are pinned (locked + anchor); the third is always solved for the target EV. | Matches spec §4.3: the dials always describe one equivalent exposure, and turning any dial re-solves the third axis for the current reading. |
| 2026-09-22 | While a reading is held, incoming samples never re-solve the dials. | The held reading is a fixed reference for composition and framing (FR-4); dial targets move only while live. |
| 2026-09-23 | `MeteringSource.applyConfiguration` is a protocol requirement, not an extension-only default. | Extension defaults do not dispatch through the existential: the controller would call the no-op default and the camera would never receive mode/Spot context. A requirement with a retained default keeps fixtures simple. |
| 2026-09-23 | Permission recovery observes `UIApplication.didBecomeActiveNotification` instead of `AVCaptureDeviceWasAuthorized`. | The iOS 27 SDK removed the `AVCaptureDevice` authorization notification; the app returns to the foreground after the user changes the camera permission in Settings, so re-syncing there is the remaining supported path. |
| 2026-09-23 | The default feed is the real camera; the fixture feed is reachable only through the DEBUG bar. | Phase 2c swaps the default behind the same seam (an earlier decision made the DEBUG feed default while the camera did not exist). The DEBUG bar keeps spec 8.5 testability. |
| 2026-09-23 | Feed swaps reset `MeterEngine` state before the new feed is configured. | Rate cap and last-reading state are per-feed; without the reset a new feed's first sample would be rate-capped against, or answered with, the old feed's reading. |
| 2026-09-23 | The Spot point is stored in the capture buffer's unit square; all screen↔capture conversion happens at the boundary via `SpotPointConverter`. | `exposurePointOfInterest` and the luma Spot box both live in buffer space, while the reticle must appear where the user tapped. One pure converter (90° CW back-camera rotation + aspect-fill crop, clamped) keeps the point of interest, the luma box, and the reticle mutually consistent and unit-testable. |
| 2026-09-23 | Lens switching replaces the video input on the running session (begin/commit configuration), restoring the previous input if the swap fails. | Spec FR-1 requires lens switching to reconfigure the session cleanly without dropping the session; the smoothing-window reset still flows through the normal config path so the engine and camera stay in lockstep. |
| 2026-09-23 | The session preset is 1920×1080 and the nominal buffer size (1920×1080, sensor orientation) is the Spot-conversion constant. | The preview needs real resolution; the preset defines the buffer aspect the converter models. If a device's active format differs slightly, the normalized POI error is sub-percent and the clamp keeps it valid. |
| 2026-09-23 | The meter screen forces the dark scheme and renders the spec §4.7 tokens (dark backdrop, 68% black panels, amber accent) over the live preview. | The preview can be any scene (bright outdoors included); a fixed dark control layer with scrims keeps the readout legible in all lighting, which the spec's outdoor-legibility rubric requires. |
| 2026-09-23 | "Nearby" combinations = the anchor axis stepped by every table offset within ±1 full stop, with the locked axis fixed; out-of-range solves dropped, nearest-first, capped at 5 rows. | The spec shows a "compact list below the wheels" of nearby equivalent combinations without defining the span. ±1 full stop covers the trade-off a photographer actually wants to scan, the locked axis is the user's commitment, and the pure `EquivalentCombinationFinder` keeps the rows consistent with the dials. |
| 2026-09-23 | Any dial edit (wheel turn or combination row) auto-enters Hold while Live, but only when a real reading exists. | Spec §4.3: "Turning an exposure wheel while Live automatically enters Hold before applying the edit." Freezing first makes the edit solve against a stable target (so an applied row matches exactly); gating on a real EV avoids entering Hold with nothing to study. |
| 2026-09-23 | High noise counts as a dark scene only when the center luma is below `noiseJudgeLumaCeiling` (0.5); the luma dark check is unchanged. | On-device, the "Too dark — use a tripod" warning flapped in bright outdoor light because the noise metric (mean 1-pixel difference) spikes on fine texture. Luma stays the primary dark judge; noise becomes a secondary signal that applies only to scenes that are not already bright. |
| 2026-09-23 | The meter screen pins its top (lens/mode) and bottom (Hold/Save) bars with `safeAreaInset`, sizes the dial responsively (192 pt, down to 160 pt), and reserves a fixed 48 pt slot for the confidence banner. | On a Dynamic-Island iPhone the lens picker sat under the status bar and the Hold button clipped off the bottom edge, and the layout jumped whenever the banner appeared or cleared. Pinned insets keep the primary controls on screen and hittable; the fixed slot removes the reflow. |
| 2026-09-23 | The UI shows the three nearest nearby-combinations rows; the domain `EquivalentCombinationFinder` keeps its five-row cap. | Vertical space on the meter screen. The controller asks for `limit: 3`; the domain API keeps its general default for reuse, and its existing tests are untouched. |
| 2026-09-23 | The in-app About is a compact sheet from an info button in the bottom bar, and its version line is read from `Bundle.main` (`CFBundleShortVersionString`/`CFBundleVersion`), never hardcoded. | Release readiness needs a visible version and support path, but the spec defines no About screen; a sheet keeps the packed single-screen meter clean. Reading the bundle (which the build settings generate via `GENERATE_INFOPLIST_FILE`) keeps the displayed version identical to the authoritative build metadata, including the build number. |
